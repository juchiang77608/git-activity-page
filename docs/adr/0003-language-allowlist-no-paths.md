# ADR-0003：語言 allowlist，不公開路徑

- **狀態**：已接受
- **日期**：2026-09-10（依既有實作公開整理）

## 背景

語言分佈對履歷／作品集有用，但「依副檔名統計」很容易把路徑或怪檔名帶進公開 JSON（例如未知副檔名、或誤把路徑當鍵）。

## 決策

1. 本機同步時只持久化 **語言顯示名 → 檔案觸及次數**，不存路徑。
2. 公開匯出再套一層 **allowlist**（TypeScript、Python、Vue 等已知語言名）。不在名單內的鍵直接丟棄。
3. 鍵名還需通過安全字元檢查：拒絕 `/`、`\`、`..`、開頭的 `.`。
4. 公開頁只呈現語言名與次數，不呈現副檔名。

本 repo 的名單維護在 `scripts/export.py`；本機蒐集端使用同一組語言名，避免一邊寫了公開檔讀不到的鍵。

## 理由

- Allowlist 比「刪掉看起來像路徑的字」少漏網。
- 未知副檔名若原樣輸出，等於洩漏專案慣用的內部檔型。
- 次數以「檔案觸及」計，不需要（也不該）帶路徑才能加總。

## 後果

**正面**

- `activity.json` 的語言鍵可預期、可審查。
- 熱力圖年份切換時，語言條可安全跟著變。

**負面**

- 名單外的語言不會出現（例如冷門副檔名）。
- 兩邊名單若沒同步，匯出端會默默丟鍵，統計略偏低。

## 替代方案

| 方案 | 未採用原因 |
|------|-----------|
| 公開原始副檔名 | 可能洩漏內部工具鏈或產生器檔 |
| 用 repo 名稱猜語言 | 多語言 repo 會嚴重失真 |
| 只統計本 repo 的 linguist | 不含本機其他專案 |
