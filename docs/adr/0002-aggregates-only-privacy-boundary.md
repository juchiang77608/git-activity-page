# ADR-0002：公開資料僅含聚合統計

- **狀態**：已接受
- **日期**：2026-09-10（依既有實作公開整理）

## 背景

本機資料庫為了除錯與對帳，會保存比公開頁所需更多的欄位。若「整庫同步」或「把查詢 API 接到 GitHub Pages」，隱私邊界會變成預設全開。

需要一條明確規則：什麼可以離開本機，什麼不行。

## 決策

離開本機、進入本 repo 的資料**只准**以下形狀（`activity.json`）：

- 每日 commit 次數：`日期 → 整數`
- 語言檔案觸及次數：全域合計，以及依年合計
- 匯出時間與總筆數

明確排除：repo 名稱、檔案路徑、commit 訊息、作者、diff 行數、原始副檔名。

匯出腳本以白名單 key 寫檔；多出來的欄位直接拒絕寫入。

## 理由

- 熱力圖與語言條只需要次數，不需要識別單一 repo 或檔案。
- 聚合之後，無法還原「哪一天改了哪個客戶專案」。
- 規則寫在匯出層，比事後從頁面上藏欄位可靠。

## 後果

**正面**

- 公開檔可用肉眼審查：不該出現路徑字元、repo 字串。
- 頁面 footer 能誠實說明資料範圍。

**負面**

- 無法做「依 repo 篩選」或「點格子看 commit 列表」這類展示。
- 次數含私有與公開 repo，外人無法核對單日細節——這是刻意的。

## 替代方案

| 方案 | 未採用原因 |
|------|-----------|
| 公開 repo 清單、隱藏訊息 | 清單本身已足以對應客戶／雇主專案 |
| 只統計已 push 的 GitHub repo | 失去追蹤本機活動的目的 |
| 匿名化 repo 名（repo-1, repo-2） | 數量與活躍度仍可能被對上已知專案 |
