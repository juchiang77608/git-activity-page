# ADR-0004：離線匯出、手動發布

- **狀態**：已接受
- **日期**：2026-09-10（依既有實作公開整理）

## 背景

本機資料庫與公開頁必須保持斷開（見 [ADR-0001](0001-local-collect-public-static-slice.md)）。若 Pages 上的 JS 去打本機 API，一般訪客會失敗；若本機綁定區網，又違反「API 不對外」的前提。

仍需要一條更新公開數字的路。

## 決策

1. 以 `scripts/export.py` 在本機、離線讀取 SQLite（唯讀），寫出 `activity.json`。
2. 人工檢查後 `git commit` / `git push`，由 GitHub Pages 提供靜態檔。
3. 公開頁只用 `fetch('activity.json')`，無其他後端、無定時爬蟲、無 webhook。
4. 含本機絕對路徑的操作指令若需要，放在不進版控的目錄，不寫進 README。

## 理由

- 更新頻率低（人為「發布一版統計」），不值得做常駐同步。
- 每次發布都經過 git，公開檔可 diff、可回溯。
- 靜態 `fetch` 讓本機預覽與 Pages 行為一致（皆需 http server，不能直接開檔）。

## 後果

**正面**

- 公開站零營運：無程序、無密鑰、無可被打的 API。
- 匯出失敗不會自動污染線上檔。

**負面**

- 熱力圖會過期，直到下次手動匯出。
- 忘記更新時，訪客看到的是舊節奏。

## 替代方案

| 方案 | 未採用原因 |
|------|-----------|
| 公開頁直連本機 API | 訪客連不到；也擴大攻擊面 |
| GitHub Action 定時跑匯出 | Action 沒有本機 DB |
| 把 DB 放進私有雲再讓 CI 讀 | 等於把蒐集層搬上雲，偏離 local-first |
